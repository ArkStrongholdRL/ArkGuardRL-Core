# Learned search-and-adapt parent options

Opt in with `planner['options'] = dict(search_options.CONFIG)`. This is a new
input/model/controller contract, not a reinterpretation of strategic-options/v1.
Legacy target relations cannot be mixed with this contract. Native action
support, fixed band, reward, gamma and termination semantics are unchanged.

The parent can begin without a material or final direction. Public owned and
affordable visible ordinary chess families form a 128-row asset table. A learned
choice can defer, commit now, or request upgrade-before-merge on any current
path. Retargeting preserves parent identity, start, duration and total accepted
economic debit; retargeting within the same realization also preserves its
upgrade evidence. Timing is a learned intention verified against actual
feedback, never a scripted purchase/upgrade restriction.

Actual front offers receive occurrence identities; changing only queue length
does not create a new front offer. An accepted reward consumes that occurrence,
including when the next queued offer has identical public slots. New offers and
actual acquisition receipts permit same-PREP choices, independent of the old
once-per-round selector. Each ordinary public opportunity is deduplicated, with
eight ordinary choices per round. Offer/use events remain bounded by actual
native PREP actions. Choosing a real offer or use can adopt a parent even if
none was active. Multiple acquisition receipts queue separately.

Offer choice, actual acquired object and material have separate identities.
Use choices are undecided, reinforcement, bridge, or growth around an actually
acquired object's non-disabled public bond. Materials are not protected and
need not be deployed. Parent debit/horizon closure cannot drop an outstanding
offer/use receipt before its handoff; a closing use choice is supplied to at
least the next native attempt, or closing Ready/exit ends the parent. This is
memory closure, not extra execution budget or a claim of successful deployment.

The CPU float context has 40 header fields and 128x8 public asset facts (1064
slots). Catalog IDs use the existing frozen identity embedding; asset paths
pool separately. A zero-initialized projection conditions independent native
economy/placement heads and critic. Twenty role/phase facts add independent
zero-initialized economy/placement/schedule deltas. They are facts, not reward
labels, action masks or assumed strategy preferences.

Collection, strict checkpoint identity, scalar/state-local batch, row and
columnar transport, and separate live SMDP PPO use the same schema dispatch.
Native PPO remains conditional on the actual sampled upper choice; upper PPO
reuses actual native reward sums and settlement lambda. Parent decisions use a
pre-choice critic; native bootstrap uses the current parent context, never the
action-dependent relation tensor. Archived, human and teacher rows have no
admission route. Re-encoding verifies ordered menus, receipts, contexts,
relations and recorded behavior probabilities before learning.

New selector/projection modules require explicit adoption and new initialization;
old checkpoints and sealed source hashes are never rewritten. No tests,
fixtures, engine/data modifications or claim of improved play are included.

Native recovery v2 also covers the reproduced PREP64 single-temp-item case:
the sole supported sequence is destroying that exact temp item then accepted
Ready, at most two attempts. Ordinary unequipped single-chess recovery retains
its three-attempt support. No equipped/multiple-piece scope, sale ranking,
economic preferences or post-sampling overrides are added. Tensor layout stays
8-wide; the explicit config/schema and provenance distinguish the new domain.
