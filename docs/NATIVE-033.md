# 0.3.3 原生迁移状态

目标是纯 Rust 环境及薄 Python 接口，行为对齐 Stronghold Protocol
`41bbca5712ac08394bbc4d5b4e3411c6be1634b6`，不兼容旧模型。

当前实现是基础阶段，**还不能运行 Rust 完整对局**。现有安装仍提供旧 Node 环境；
没有注册未完成的 `ArkGuardRL-v1`，也没有取得完整 env 的 5 倍加速结果。

`crates/engine` 已实现 mulberry32、UTF-16 种子派生、独立随机流、确定性数学、
有容量限制的虚拟事件队列、外部 JSON 目录加载和进度奖励公式。
目录保留 JSON 对象插入顺序，数值 ID 单独排序；未来规则遍历还需匹配 JavaScript
对整数键的枚举顺序。输入字节预算不等于解析后内存预算。

`crates/python` 提供可编译的 PyO3 开发绑定，只暴露数据目录与种子派生，
尚未接入正式 Python 安装。`powi` 只接受模拟器使用的有限基数、i32 整数指数域，
域外显式报错，不使用平台相关的 `powf` 替代。

战斗基础已加入 `battle` 模块：四方向旋转、Boss/隐藏关坐标映射、地形与障碍查询、
SPFA 双流场、视线平滑、深水区避让、格心与非格心直线移动，以及路径长度。
流场缓存最多 64 项，障碍改变时失效；已返回的流场通过独立只读引用保留快照。
已用外部数据的全部 13 张地图、三种矩形范围、有无障碍和两种寻路开关对照
1,248 个完整流场，并比较路径点、几何长度、方向与部署坐标。

单位数值层已加入 `battle/stats.rs`：增益加算/乘算、独立闪避、练度乘区、属性限幅与
溢出回退、延迟重算、最大生命变化时保留血量比例，以及浮空/缚地优先级。
`battle/damage.rs` 提供物理、法术、真实与元素伤害的纯计算，含穿透顺序、理论伤害、
已结算伤害旁路和来源/目标倍率。768 组属性场景、3,072 组伤害场景已逐位对照上游。
数值层仍使用内部映射表达修饰项，尚未取得完整战斗性能结果。

`battle/injury.rs` 已实现按优先级/获取顺序执行的伤判层：同名减伤取最高值、类型护盾、
次数盾、独立闪避、取消掩码、观察回调与延迟清理。原生 Hooks 接口支持回调移除效果和
嵌套伤害，稳定身份保持当前命中快照；最外层执行结束回收已移除条目。
效果数量、嵌套深度与延迟回调数量均有限制，超限显式报错。
1,024 组上游对照覆盖最终伤害、效果消耗、回调顺序及随机数状态；嵌套、清理错误和
同优先级顺序另有原生测试。技术回调错误通过 Result 上报，不能当作合法伤害样本。
当前 Hooks 是 Rust 内容分派接口，各单位/技能的实际处理器仍待移植。

`battle/health.rs` 已加入最终 HP 应用、生命流失、Boss 限伤、共享血池同步、致命伤害救回、
伤害/治疗归属统计、特殊次数生命，以及普通治疗、生命回复、直接恢复和过量治疗分派。
768 组上游对照检查 HP、归属统计和事件顺序。
单位、血池与玩家统计注册表限制容量，重复身份及超限报错；永久移除的单位可在 tick 末释放，
待重部署的单位仍保留。治疗回调导致死亡、regen 忽略治疗量改写、restore 绕过禁疗另有测试。击杀与过量护盾通过 Rust host 接口分派，
真实单位移除/重部署、技能处理器和共享血池的特殊内容仍由后续 battle 层实现。

`battle/hit.rs` 已连接 HP 伤害路径：入口保护、hit、来源/目标计算、output、beforeApply、
applying、Boss 限伤、伤判、hpDamage、HP 应用和延迟清理。各阶段保留属性刷新及存活检查，
precomputed/resolved 分别跳过上游规定的阶段，闪避模式按原时点捕获。
1,024 组完整路径对照比较事件顺序、HP、护盾、归属统计和随机数状态。
元素损伤量表、伤害转移内容、具体技能处理器仍待接入；当前入口只处理 HP 伤害。

`battle/clock.rs` 已实现 1/30 秒 tick 的阶段调度、重入保护、阶段末强制结束、
清理顺序和结束条件。时间按整数 tick 乘固定步长计算，运行预算耗尽保留活状态。
256 组上游调度/结束条件对照通过；首次结束请求优先，强制结束归一为 forced，超时归一为 timeout。
阶段技术错误会将时钟置为 faulted，拒绝继续采集。具体单位更新仍由 host 阶段处理器提供，
此调度器尚不具备独立模拟整场战斗的能力。

`battle/deploy.rs` 已加入部署、移动、击杀救回、撤退、倒地位置与占格、重部署计时、
DP 支付/失败退款和 tick 末释放。单位状态直接使用 World 中的同一份记录，另保留有界的
初始棋盘位置，确保已释放召唤物仍参与倒地回位规则。384 组上游对照覆盖状态、DP 和事件顺序。
技能重置、临时效果清理和内容回调通过必需的 host 方法分派；carry/保留 SP、设备障碍、
悬赏和完整结算计数仍需接入具体运行时，尚不能独立运行整个部署与技能系统。

`battle/blocking.rs` 已实现地面/飞行/设备接触半径、重量容量、围栏与起飞限制、
最近阻挡者和行列顺序决胜，以及双向阻挡关系的建立/释放。1,024 组上游对照覆盖接触、
重复查询和两种释放路径。移动、撤退和敌人移除直接清理关系；仍有关联的单位不能释放。
隐匿恢复通过必需 host 回调分派，完整索敌和隐匿内容尚待实现。

`battle/targeting.rs` 已加入敌我目标可选条件、光环/范围效果过滤、范围旋转与扩展、
敌我目标排序和攻击目标数量计算。排序保留优先对空先于阻挡的例外、仇恨、剩余路径和
出现顺序，并按 JS comparator 处理无穷距离的平局。512 组上游场景覆盖过滤与 16 种优先级。
按来源隐匿恢复、技能排除和几何距离由显式 Queries 接口提供，未用简化规则代替内容实现。
`battle/cadence.rs` 已实现冷却帧容差和攻击前锁定的资格检查，1,024 组上游锁定条件对照通过；
冷却可直接更新 World 单位状态。阻挡容量下降会从最后阻挡的敌人开始释放。
`battle/search.rs` 已实现 acquireTargets 的治疗血量阈值/多目标、要塞近战与本格后备、
阻挡目标补入、特殊友方目标和 allInRange 分支，并提供按 tick 替换的有界攻击锁定缓存。
缓存仅保留活目标，回放重新检查可选性；超限报错并清除旧缓存，不裁剪候选域。
512 组上游搜索与攻击锁定场景通过，覆盖死亡/不可选后的过滤。
几何范围搜索仍由显式 host 查询提供。
`battle/sp.rs` 已加入技能 SP/充能账本：费用乘区和最终加算、充能累计、携带总技力、
费用变化重整、SP 回调后的费用重读、阻回与运行中技能锁定，以及独立于眩晕的自然恢复。
768 组上游操作序列逐位对照通过，另测试整 tick 恢复容差、免费技能和携带状态。
`battle/skills.rs` 已连接技能生命周期：reset/carry、激活/结束、持续时间、弹药、攻击/受击回复、
自动操作冷却、pending 攻击、触发条件路由、withdrawn 退款与 onEnd 重开保护。
几何触发条件及具体内容通过显式 host 分派，回调递归与技术错误会使运行时失效。
384 组连续技能操作序列对照状态和事件顺序，另验证真实命名增益的结束/重开顺序。
`battle/ally.rs` 与 `battle/attacks.rs` 已把锁定/重选、冷却、技能和直接攻击主目标载荷接通。
生产直接攻击执行器处理多段伤害、实例倍率、治疗、攻击身份/归属与攻击后技能处理。
24 组 240 tick 的连续场景（5,760 tick）逐帧对齐上游的技能、updateAlly、performAttack 和 HP 路径。
这些场景以显式范围成员替代几何移动；尚不代表全内容战斗对齐。
`battle/projectiles.rs` 已实现有界追踪弹道：同部署身份追踪、死亡/隐藏处理、hitDead、
寿命上限、飞行回调取消和下一 tick 才移动的新投射物。128 组 30 tick 的上游弹道对照通过。
投射物保留来源/目标单位，退场时先清理内容钩子，最后一条引用释放后再回收单位记录；
清队列和回调错误都会释放引用。攻击执行拆为 prepare/impact/finish，远程攻击在发射后
立即处理弹药/SP，命中时读取当前 ATK，并保留发射时的技能倍率和攻击身份。
连续战斗对照已扩展到远程、治疗和射手死亡后命中；范围成员仍为显式夹具。
溅射、链式、回旋镖往返、职业专用载荷、具体技能内容和完整几何查询仍待实现，不能以直接攻击近似。

后续需实现单位/技能内容和各 tick 阶段的具体处理器，
以及局内状态机、公开合法动作、结构化观测和批量环境。
这些模块仍未接成可运行完整对局的环境。
奖励模块只接受已确认的完成轮次与结局，未来 match 层负责从真实结算生成这些输入。
这些部分完成并通过逐决策对照前，不能删除现有可运行实现。

## 开发验证

```sh
cargo test -p arkguard-engine --release
ARKGUARD_REFERENCE_ROOT=/path/to/game cargo test -p arkguard-engine --release -- --include-ignored
ARKGUARD_REFERENCE_ROOT=/path/to/game python -m unittest discover -s tests -p test_reference033.py -v
PYO3_PYTHON=/path/to/python3 cargo build -p arkguard-python
```

基础对照测试直接读取上游函数输出，逐位比较 RNG、数学与调度结果，不需要游戏数据。
地图对照测试读取外部 stages.json，只运行地形和寻路，不运行对局。
属性和伤害对照只调用上游数值模块，不需要游戏数据或运行对局。
Python 对照入口测试会创建四种难度的对局并推进到首个选盟约决策点，不运行训练。

开发期 JSONL 对照入口：

```sh
node tools/reference/session.mjs /path/to/game
```

stdin 每行一条命令，例如 `{"cmd":"reset","seed":42,"difficulty":"ABYSS"}`、
`{"cmd":"step","action":{"t":"g.infoReady"}}`、`{"cmd":"close"}`。
`step` 执行明确动作并推进到下一决策边界；返回公开状态、动作接受标志和回调预算截断。
它尚不枚举新动作域，也不构造最终结构化张量，因此不能直接用于最终性能验收。
