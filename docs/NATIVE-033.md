# 0.3.3 原生运行时与迁移笔记

当前入口为 `ArkGuardRL-v1`，支持原生账本、候选参数准备、索引执行、slots 并行、公开空间增量输入和渲染回放。当前验收及用法见 [性能与验收说明](benchmarks/README.md)。

下文按阶段保留迁移实现笔记，其中测试命令、数量、main 状态与待办描述属于对应历史阶段。测试源码及对照夹具已按要求移除。

目标：Rust 完整环境内核 + Python 薄 Gymnasium 接口。行为基线为 Stronghold Protocol
`41bbca5712ac08394bbc4d5b4e3411c6be1634b6`（0.3.3）；训练保留在 ArkGuardRL。
运行数据由用户另行提供，不打包素材、权重或轨迹。
当前仅维护绝境（`mode_single_abyss`）。后续迁移、内容补齐与验收均以绝境为范围；标准等其他模式不列入维护目标。历史多模式实现和测试记录不构成支持承诺。
迁移及上线范围限定第二期下半（`act2autochess` / `V2_2`），以本期可入池干员为准
（`visible=true`、`isHidden=false`、`isDiy=false`）。已移除干员和旧卡位不列入后续目标，同名干员使用本期卡位。

天赋、职业特性和模组仍随对应版本接入。每人保留独立 Kit，技能注册与运行对照均按此单技能范围执行，其他技能在安装前拒绝。

原生 Gym 入口为 `arkguardrl_core.native_gym` 注册的 `ArkGuardRL-v1`，Node 兼容入口为 `ArkGuardRL-v0`。Windows CI 构建三个原生模块；当前真实记录验收覆盖 63 份对局，已知差异与自选特征限制详见上方验收说明。

## 具体执行入口

`battle::runtime::Field` 已直接拥有 World、RNG、刷怪、内容、增益和时钟，
独立执行部署→刷怪/DP→状态→攻击锁定→敌人更新→友军技能/攻击→弹道→再部署→内容 tick→结算。
当前支持普通单人场、单人 Boss/隐秘核心场、上述 236 个普通/精英干员定义和本期 249 个敌人定义。
首领与部件保留身份标签，召唤、换代和触手动作接入有界分支及预设路线。
装备已支持纯属性、攻击/治疗触发、技能叠层、受伤隐匿和持续自损。本期机关、特殊地形和地图效果见末尾验收记录；战斗盟约继续迁移。
Boss 场已接入同场首领副本共用血池，以及单人 LP、超时扣血和胜负结算。
`solo::Runner` 已接收准备好的波次与阵容，执行连续普通回合、最终攻势、隐秘核心与终局。
基础商店、持有棋子、合成奖励与上阵操作已连接单人调度器。
准备期已接入盟约成员与激活计数、持久层数、数值类特质、远见/奇迹经济与助力结算。
干员赠送、松果招募奖励、铃兰触发与白面鸮/塞雷娅特质复制已接入准备期。
装备已贯通准备期配发与战斗。后续连接其余装备、召唤物准备与模式波次生成，再接合法动作、观测和 Gymnasium。

`run(tick_budget)` 同步返回推进步数、自然结束及预算耗尽；预算耗尽保留真实后继状态，
不转成超时或重开。技术错误使执行入口失效，不能继续采样或返回有效结算。
`report()` / `enemy_states()` / `ally_states()` / `boss_state()` / `boss_round_state()` 返回独立拥有的数据；它们是内部战斗诊断接口，不能作为策略观测。
资源容量按创建参数限制，超限报错而不裁剪。数据文件字节预算仍不等于解析后的总内存预算。

开发期可直接运行 Rust 入口，无需 Node：

```sh
cargo run -p arkguard-engine --release --example field -- /path/to/data input.json 1800
```

Boss 输入在上述格式中增加 `"kind":"boss"` 或 `"kind":"hidden"`，以及
`"bossPool":{"maxHp":100000,"hp":100000}`。省略 `hp` 使用满血，`maxHp` 至少为 1。
这两种场的缺省时限为无限，仍保留 3600 秒硬上限。CLI 的 `row`/`col` 沿用战场绝对坐标，
Boss 场范围为行 0–5、列 0–20。Rust 入口为 `Field::new_boss(..., BossConfig)`。

单人回合可增加 `"bossRound":{"lp":10,"overtime":{"afterReal":120,"combatTimeScale":2,"lpPerSecond":1}}`。
`overtime` 可省略，存在时按战场时钟折算真实秒，超过 `afterReal` 后逐整秒扣血。
Rust 使用 `configure_boss_round(BossRoundConfig)`，`boss_round_state()` 和报告的 `bossRound` 返回剩余 LP、各类损失及终局原因。

输入使用原版的 `stage` 或 `stageId`、`routes`、`spawns`、`seed`、`timeLimit`；
友军可省略，或添加 `{"players":[{"playerId":"p","units":[{"chessId":"chess_char_1_02_a","uid":1,"row":10,"col":6}]}]}`。
可用 `"skillIndex"` 选择对应 Kit 已接入的技能；不接受物品、模组或潜能覆盖。例如地形可用 `{"rows":["..."]}` 的原版形状；
实际关卡包含尚未移植的装置/地形时会报错。
此工具用于开发运算，不计作完整环境或性能验收。

连续单人回合使用 `solo::Runner`。`RoundPlan` 提供波次、收入、时限与部署上限，
`ready(PreparedRound)` 接收当前准备期的阵容和激活盟约层数，`advance(tick_budget)` 推进到下一准备期或终局。
`spend` 为准备期动作提供扣款入口。非法阵容在消耗回合计划前拒绝，执行错误使整局失效。
该入口接收预先准备的波次。阵容可由 `PreparedRound` 提供，或通过 `enable_preparation` 启用持有库存，随后用 `prep_action` 操作并调用 `ready_owned`。
启用准备期内容使用 `new_with_preparation`，初始获得先于首轮收入，`ready_current` 从持有状态计算激活层数。
其余装备效果、召唤物准备、模式波次生成及战斗盟约效果/成长结转继续连接。

```sh
cargo run -p arkguard-engine --offline --release --example solo -- /path/to/data planned-run.json 100000
```

单人 CLI 输入包含 `stage`、`seed`、`config` 和 `plans`。
`config` 使用 `lp`、`lpCap`、`keepFunds` 与可选的 `hidden`，后者含 `layerThreshold` 和 `minLp`。
每项计划使用 Field 的 `routes`、`spawns`、`overrides` 等波次形状，另提供 `kind`、`timeLimit`、`income`、`deployCap`、
`prepared` 和可选的 `spend`。Boss 计划增加 `maxHp` 与可选的 `overtime`。
`prepared.units` 沿用 `chessId`、`uid`、`row`、`col`、`dir`，可选 `skillIndex` 与装备 ID 数组 `items`。`prepared.activeLayers` 提供准备完成时的激活层数。
所有准备坐标使用行 9–12、列 2–10，单人调度器将 Boss 场位置向上平移 7 行。
输出 `ticks`、`budgetExhausted` 和整局诊断 `state`。

操作驱动的准备期在顶层增加 `"preparation":{"modeId":"mode_single_normal"}`。
可选的 `banned` 指定禁用基础干员，`initial` 以 `{"kind":"chess","id":"..."}` 或 `{"kind":"item","id":"..."}` 设定初始获得，
`capacity` 限制持有库存与奖励队列，默认 256。商店使用模式及全局经济数据和独立 shop RNG。
手动 ban 入口沿用 `preparation.banned`，例如 `{"modeId":"mode_single_normal","banned":["chess_char_1_02_a"]}`。
这是原版的卡池禁用：从商店及按卡池抽取的奖励中移除基础干员，初始配置、定向赠送和直接复制仍沿用各自规则。
后续按种子生成模式的入口必须保留此参数，将手动名单与自动 ban 结果取并集；手动名单不参与地图、阵营、Boss、波次的 RNG 抽取，同一种子修改手动名单不应改变这些生成结果。该模式生成入口尚待实现。

### 不屈：即时再部署、倒地技力与替身储存

### 突袭：选敌、跳跃与复活重选

### 持久原生会话与 Python 执行入口

`solo::session::Session` 与开发绑定 `NativeSolo` 已接通绝境种子生成、准备期、机变选择、战斗和结算。构造时指定三个受支持核心之一及手动禁卡；多个会话共享只读 `NativeCatalog`，各自保存状态。`reset(seed)` 替换整局，`step(action_json, tick_budget)` 提交一个原有 `g.*` 动作（包含 `g.ready`），自动推进至下一个决策或预算边界；`advance(tick_budget)` 仅续跑已暂停的战斗。每次最多推进 108000 帧，允许预算为零，预算耗尽不表示 episode 截断。

返回回执区分正常拒绝、待决策、战斗暂停和真实终局。格式错误不消耗 revision；规则拒绝保留钱包、库存和 RNG。内容或执行错误使会话失效，不伪造终局。Python 的生成、动作和战斗调用释放 GIL；`close()` 释放当前对局，随后可重新 reset。`diagnostics()` 明确是含私有状态的调试入口，不作为策略观测；本批不改变模型输入或注册新 Gym 环境。

开发验证入口：先运行 `cargo build --release -p arkguard-python` 和 `cargo build --release -p arkguard-engine --example solo`，再以 `ARKGUARD_REFERENCE_ROOT`、`ARKGUARD_NATIVE_LIBRARY`（所构建的 `_native` 动态库路径）和 `ARKGUARD_SOLO_BINARY`（solo 示例路径）运行 `python -m unittest discover -s tests -p test_native_session.py`。
